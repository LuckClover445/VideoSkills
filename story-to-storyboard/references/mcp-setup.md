# prompt-optimizer 配置指引

**当前状态：停用。** prompt-optimizer 尚未完善，技能默认不执行本文件任何步骤，也不读取本文件。仅在用户明确要求启用绘图提示词优化时，按下列内容操作。

**阅读指引**：仅在技能启用该能力、执行前检测发现当前会话未挂载 prompt-optimizer、且用户选择「立即配置」时读取。配置由当前 agent 自行执行；仅当本机写权限、配置文件位置或客户端重启无法由当前 agent 处理时，才改用第三节的配置提示词交给用户。本技能不改变该 MCP 服务的参数，也不创建任何替代服务。

## 一、服务参数

| 项 | 值 |
| --- | --- |
| 名称 | `prompt-optimizer` |
| 传输类型 | 远程 HTTP（客户端写作 streamable HTTP、HTTP 或 SSE，按其支持项选择） |
| URL | `http://47.251.140.61:8081/mcp` |
| 鉴权 | 无（不需要 API Key，无本地依赖） |

配置片段（供核对目标结构，不得用它整体覆盖用户现有配置）：

```json
{"mcpServers":{"prompt-optimizer":{"url":"http://47.251.140.61:8081/mcp"}}}
```

## 二、由当前 agent 执行的配置步骤

按下列顺序执行，任一步失败即转入第六节处置，不得跳步硬写。

1. **确认客户端与配置文件位置。** 先判断当前客户端类型（Claude Desktop、Cursor、VS Code + Cline、其他支持 MCP 的客户端），再定位其 MCP 配置文件；无法判断客户端，或按已知约定找不到文件时，向用户确认路径，不得凭猜测在任意目录新建配置文件。
2. **读取并备份。** 以只读方式读取现有文件，保留其原始编码与格式；写入前在同目录复制一份同名 `.bak`。文件不存在则按客户端要求的格式新建。
3. **只做合并。** 在 `mcpServers` 下新增 `prompt-optimizer` 条目，原有条目与字段逐字保留，不整理、不重排、不删除、不添加注释。已有同名条目时：URL 一致则不做改动并回报已存在；URL 不一致则先说明现状，等用户确认后再改。
4. **写回并校验。** 写回后校验 JSON 可解析、编码与客户端要求一致、无多余逗号与注释；不通过则用备份还原，并说明失败原因。
5. **复检。** 重新读取当前会话的 MCP 服务与工具列表，确认 prompt-optimizer 及其工具已可用。需要重启客户端才能在会话内可见的，如实告知用户，并按第六节处置。
6. **回报三件事。** 改了哪个文件、新增了哪些内容、是否需要重启才生效。

禁止事项：不创建 MCP 服务器、代理或端口转发；不改动该配置文件以外的内容；不写入任何凭据；不得为了通过检测而伪造工具或跳过校验。

## 三、配置提示词（备用）

当前 agent 无法写入本机配置，或用户要求自行安装时，把下方整段原样输出给用户，由其复制到能操作本机配置的 agent 对话中。不改写、不增删条款、不替换名称与 URL。

```text
请在本机新增一个远程 MCP 服务，只做这一件事。

服务参数：
- 名称：prompt-optimizer
- 传输类型：远程 HTTP（客户端若区分 streamable HTTP / SSE，按其支持项填写）
- URL：http://47.251.140.61:8081/mcp

执行要求：
1. 判断我当前使用的客户端（如 Claude Desktop、Cursor、VS Code + Cline、其他支持 MCP 的客户端），据此确认其 MCP 配置文件位置；无法确定时先问我，不要猜路径。
2. 读取现有配置文件；文件不存在则新建。写入前把原文件备份为同目录同名 .bak。
3. 只做合并：在 mcpServers 下新增 prompt-optimizer 条目，原有条目与字段逐字保留，不做整理、不重排、不删减。
4. 若已存在同名条目：URL 一致则回报「已存在，无需修改」；URL 不一致则先说明现状，等我确认后再决定是否改写。
5. 写回后校验：JSON 可解析、编码 UTF-8、无多余逗号与注释；校验不通过则用备份还原并说明原因。
6. 完成后告诉我三件事：改了哪个文件、新增了哪些内容、是否需要重启客户端才生效。
7. 不要创建任何 MCP 服务器、代理或端口转发；不要改动该文件以外的内容；不要写入任何凭据。

说明：该服务是纯 HTTP 远程服务，URL 须逐字保持一致（http、端口 8081、路径 /mcp），不需要本地安装依赖，也不需要 API Key。
```

## 四、客户端界面手填

用户不愿改配置文件时，可按客户端 MCP 设置界面手动添加，填三个字段：

| 界面字段 | 应填内容 |
| --- | --- |
| 名称 / Name | `prompt-optimizer` |
| 类型 / Type | HTTP（或 Streamable HTTP） |
| URL / 地址 | `http://47.251.140.61:8081/mcp` |

界面要求填写请求头或鉴权时留空，不得自造 Token。

## 五、配置后的验证

1. 重新加载 MCP 服务列表，或按客户端说明重启。
2. 确认工具列表中出现 prompt-optimizer 提供的工具；工具名可能不是 `optimize_prompt`，以实际列表为准。
3. 回到技能第 0 步复检；通过即继续第 1 步，第 2 步按「调用契约」使用。

## 六、失败处置

| 现象 | 处置 |
| --- | --- |
| 找不到配置文件或无法确认客户端 | 向用户索取路径或客户端类型；仍无法确认则转第三节，由用户处理 |
| 无写权限、写入被拒 | 保留备份不动，转第三节，交付说明注明未完成配置 |
| 写回后校验不通过 | 用 `.bak` 还原，说明失败原因，按未挂载继续 |
| 配置已写入但会话内不可见 | 告知需重启客户端；本轮按未挂载继续，不等待，交付说明注明 |
| 工具可见但调用超时或报错 | 最多重试一次；仍失败则该组跳过，标注「未优化（连接失败）」 |
| 用户明确不配置 | 不再询问，全程跳过优化，按原提示词交付 |
