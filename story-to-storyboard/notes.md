# story-to-storyboard 规划笔记

本文件记录尚未采纳的改进设想，不参与技能执行，不作为任何判断依据。
技能本体位于 `.user_skills\story-to-storyboard\`，其规则以技能内文档为准。

## 一、待评估的设想（原文保留）

1. 引入多 Agent 架构，可以包括作者 Agent（负责起草）、编辑 Agent（润色逻辑）、评论家 Agent（从读者视角提出质疑）、"捣蛋鬼" Agent（Trickster，专门引入意外转折）等。
2. Agent 接入网络搜索或 RAG，让它每次创作前都能"阅读"一些新素材（如相关的科普短文、儿童诗、新闻中的温馨故事），并根据这些素材进行创作。可以接入儿童文学网站、科普数据库、绘本评论、甚至本地存储的经典绘本摘要等，构建一个专属的"灵感知识库"。
3. 模块化"故事前提"随机组合（Modular Premise Synthesis）。

## 二、与技能现状的对应关系

| 设想 | 当前状态 | 说明 |
| --- | --- | --- |
| 多 Agent 分工 | 未采纳 | 技能为单流程文档，起草、润色、质疑均由同一轮完成；分角色会引入额外上下文与产物交接成本 |
| 联网与 RAG | 部分预留 | 主题发现（`story.md` 6.1）已按文档规则预留来源位，当前标记为不可用；创意路径（`creativity-path.md` 第三节）预留取值来源 |
| 模块化前提 | 部分落地 | 创意路径已按模块组织（主题/主角不可抽，背景限主题环境内，事件/结局/转折可抽），条目要求写成关系模板 |

## 三、若要推进，先解决的前提

- 多 Agent：需明确各角色的产物格式与交接点，否则等于把一次改写拆成四次重述。
- 联网与 RAG：需先定"只取结构、不取他人角色与原文句"的过滤规则，并在取回后仍过主题主体验证。
- 模块化前提：条目库若写成具体名词，会重演"抽到一口深井、月亮消失"的偏离，必须保持关系模板写法。
